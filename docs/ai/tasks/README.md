# Task handoffs

Create one `<ticket>.md` per implementation task from [TEMPLATE.md](TEMPLATE.md). If no ticket exists, use a descriptive provisional slug and link the shared task when it is created. Do not invent ticket numbers, owners, approvals or completed checks.

These files preserve branch context; they are not the live reservation board. Ownership must be coordinated through [the shared protocol](../COORDINATION.md). Avoid a central local table that every branch edits.

Keep completed handoffs as history, with their final state and PR reference. Read only the handoff relevant to the current task. Update at meaningful checkpoints, not after every command.
